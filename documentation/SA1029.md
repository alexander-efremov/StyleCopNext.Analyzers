:memo: This rule is new in StyleCopNext 2.0, and was not present in StyleCop Classic or StyleCop.Analyzers.

## Cause

A null-conditional operator (`?.` or `?[`) is split by whitespace, a line break, or a comment.

## Rule description

A violation of this rule occurs when anything appears between the `?` and the following `.` or `[` of a null-conditional operator. The operators `?.` and `?[` consist of two tokens, so the C# language allows whitespace, line breaks, and comments between them, but doing so makes the code hard to read.

```csharp
foo?         .Bar();
foo?
  .Bar();
foo? // comment
  .Bar();
foo?             [index];
foo?
  [index];
```

The `?` of a conditional expression, a nullable type, and the `??` and `??=` operators are not covered by this rule.

## How to fix violations

To fix a violation of this rule, remove everything between the `?` and the following `.` or `[`:

```csharp
foo?.Bar();
foo?[index];
```

The code fix does not offer a change when a comment or a preprocessor directive is located between the two tokens; move the comment manually.

## How to suppress violations

```csharp
[SuppressMessage("StyleCop.CSharp.SpacingRules", "SA1029:DoNotSplitNullConditionalOperators", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1029 // Do not split null-conditional operators
#pragma warning restore SA1029 // Do not split null-conditional operators
```
