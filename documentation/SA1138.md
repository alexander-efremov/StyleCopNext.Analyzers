:memo: This rule is new in StyleCopNext 2.0, and was not present in StyleCop Classic or StyleCop.Analyzers.

## Cause

A line of code is not indented the correct amount, according to the currently applied style settings for the project.

## Rule description

A violation of this rule occurs when the first token of a statement or member which starts its own line is not indented
by the amount expected for its position. The expected indentation is relative to the line which starts the containing
construct (a block owner, a type, a namespace, a property, or a `switch` statement), and uses the `indentationSize` and
`tabSize` indentation settings; the code fix also uses `useTabs`. Indentation is compared in columns, so mixing tabs and spaces to reach the
same column is not reported by this rule (see [SA1027](SA1027.md) for that).

The rule checks the following elements:

- statements inside blocks, including method, accessor and local function bodies
- members of classes, structs, interfaces and records, and members of enums
- accessors inside accessor lists
- usings, extern aliases and members inside namespaces (both block and file-scoped namespaces)
- members, usings, extern aliases, attribute lists and top-level statements at the top of a file, which are expected
  to start in the first column
- `case` and `default` labels and the statements in switch sections
- labels targeted by `goto` statements
- opening and closing braces which start their own line, which are expected at the indentation of the line that starts
  the construct they belong to

For example, the following code would produce violations of this rule:

```csharp
public void MethodName()
{
  A();     // SA1138: expected 4 columns of indentation
        B(); // SA1138: expected 4 columns of indentation
}
```

The following code would not produce any violations:

```csharp
public void MethodName()
{
    A();
    B();
}
```

This rule works alongside [SA1137](SA1137.md): SA1137 reports sibling elements which are not indented the same as each
other, while SA1138 reports elements whose absolute indentation does not match the project settings.

### Settings

The behavior of this rule is influenced by the following properties of the `indentation` object in **stylecop.json**.
See [Configuration](Configuration.md#indentation-behavior) for more information.

| Property | Default Value | Description |
| --- | --- | --- |
| `indentBlock` | **true** | Indent the contents of blocks. |
| `indentSwitchSection` | **true** | Indent `case` and `default` labels relative to the `switch` statement. |
| `indentSwitchCaseSection` | **true** | Indent the statements of a switch section relative to its labels. |
| `labelPositioning` | **oneLess** | `leftMost`, `oneLess` or `noIndent`. |

The options are also read from **.editorconfig** when they are not set in **stylecop.json**:
`csharp_indent_block_contents` (`indentBlock`), `csharp_indent_switch_labels` (`indentSwitchSection`),
`csharp_indent_case_contents` (`indentSwitchCaseSection`) and `csharp_indent_labels` (`labelPositioning`, with the
values `one_less_than_current`, `flush_left` and `no_change`).

With the default values, the following code does not produce any violations:

```csharp
public int MethodName(int value)
{
    switch (value)
    {
        case 1:
            return 1;

        default:
            goto done;
    }

done:
    return 0;
}
```

With `indentSwitchSection` set to **false**, the `case` and `default` labels are expected to be aligned with `switch`:

```csharp
switch (value)
{
case 1:
    return 1;
}
```

### Not reported

The rule is conservative. The following lines are never reported:

- continuation lines of a multi-line expression, argument list, parameter list, initializer or other construct which
  is not a statement or member
- lines inside of multi-line string literals, verbatim strings and interpolations
- code which is disabled by preprocessor directives
- lines which start with a comment, and elements which are preceded by a comment on the same line (comments are not
  elements, and are not checked)
- the contents of blocks which belong to lambda expressions and anonymous methods, and of blocks which belong to a
  labeled statement, since their position relative to the surrounding code is ambiguous
- the braces of blocks which directly belong to a switch section, and the contents of such a block unless the opening
  brace starts its own line
- elements whose containing construct does not start its own line and is not preceded by an element on that line

## Configuration

This rule is affected by the following settings in **stylecop.json**. See [Configuration.md](Configuration.md) for details. Settings that have an
**.editorconfig** key can also be set there; see [Settings in .editorconfig](Configuration.md#settings-in-editorconfig).

| Setting | Default | Effect on this rule | .editorconfig key |
| --- | --- | --- | --- |
| [`indentation.indentationSize`](Configuration.md#basic-indentation) | `4` | The number of columns of each indentation level. | `indent_size` |
| [`indentation.tabSize`](Configuration.md#basic-indentation) | `4` | The width of a tab character in columns, used to compute the column of a line. | `tab_width` |
| [`indentation.indentBlock`](Configuration.md#indentation-behavior) | `true` | When `false`, block contents are expected at the same indentation as the block owner. | `csharp_indent_block_contents` |
| [`indentation.indentSwitchSection`](Configuration.md#indentation-behavior) | `true` | When `false`, `case` and `default` labels are expected at the indentation of the `switch` statement. | `csharp_indent_switch_labels` |
| [`indentation.indentSwitchCaseSection`](Configuration.md#indentation-behavior) | `true` | When `false`, the statements of a switch section are expected at the indentation of its labels. | `csharp_indent_case_contents` |
| [`indentation.labelPositioning`](Configuration.md#indentation-behavior) | `"oneLess"` | The expected position of labels targeted by `goto`: `"leftMost"`, `"oneLess"` or `"noIndent"`. | `csharp_indent_labels` |

## How to fix violations

To fix a violation of this rule, adjust the leading whitespace of the line so that it uses the expected indentation.
The code fix updates the leading whitespace of the line according to the indentation settings.

## How to suppress violations

```csharp
[SuppressMessage("StyleCop.CSharp.ReadabilityRules", "SA1138:IndentElementsCorrectly", Justification = "Reviewed.")]
```

```csharp
#pragma warning disable SA1138 // Indent elements correctly
#pragma warning restore SA1138 // Indent elements correctly
```
